RAN4#120-bis（济州岛）NTN 相关议题报告

一句话结论：RAN4#120-bis（2026-10-12~16，韩国济州，与 RAN1#126-bis 同周同地）NTN 工作全面进入"数值收口"阶段——六大 WI 全部产出会议结论（WF/Agreement）：NR_IoT_NTN_Ph2 的 PC1.5 dual Tx 给出完整 A-MPR 起点表、NTN DL CA 从"框架"推进到"参数+CR 分工"，GNSS_resilient 拿下 RF/RRM 双 WF（工作计划批至 #124），IoT_NTN_Ph4 敲定 PC0.5 MPR、ext_guard 敲定定义与信令基线，NTN_bands_Features 多个 A-MPR/RSD 落地；6G 侧 NTN 共存（[364]）产出首份 WF（SAN 相控阵模型/受害 TN 布局/NTN-NTN ACLR 24.2dB 推导），日本 2GHz 地面频段引入 NR-NTN 新 WID 首次上会（KDDI/SpaceX 等 9 家联署）——"NTN in TN bands"主线出现实质进展信号。

2. 逐议题进展详析

2.1 主轴：NR_IoT_NTN_req_Ph2（7.6，三个并行 topic）

WID 分三个 moderator 小组：[346] 主 RF（CHTTL+Apple）、[347] HD-FDD/VSAT（MediaTek）、[348] RRM（LGE），本会各产出一份 approved WF。

2.1.1 PC1.5 dual Tx（7.6.3）— 数值收口最深（WF R4-2622102）

  • ULFPTx 模式框架（针对 n255，本 WI 只做 n255）：PC1.5 做 mode 1；PC2 做 mode 1,[2],0；PC3 做 mode 0；给出各模式测试配置表（DCI 0_1、单层、2 Tx 端口、TPMI 2/0 或 1）。
  • 相干 MIMO 要求：仅 TPMI#2 适用，复用 TS 38.101-1 cl.6.4D.4 起点（相对相位差 40°、功率差 4 dB、20 ms 窗）；TAE 复用 cl.6.4D.3（≤130 ns）——要求各公司在 #121 前分析其在 NTN 场景下的适用性。
  • 后缀：UL MIMO 用 suffix D、TxD 用 suffix G；确认 PC1.5 不需要 UTRA ACLR（n255）；SEM 沿用 NR-NTN PC3→PC1.5。
  • RSD：PC3→PC1.5 取三家提案平均（5/10/15/20MHz 分别 2.77/2.8/2.86/2.93 dB）为起点；non-handheld 2Tx 同值。
  • A-MPR（n255 NS_02N / NS_10N / NS_15N）：给出完整 A-MPR 区域与回退值表为起点，明确"将根据 #121（11 月）输入继续修改"（A1/A5-A9 区域需重点复核）。
  • CR 分工：A-MPR CR 由 Apple 牵头、其余 PC1.5 要求由 Huawei 牵头，终版 CR 归 Huawei。

2.1.2 NR NTN DL CA（7.6.6）— 从框架到参数（WF R4-2622102）

  • JSON 机制：沿用 TN 的 JSON 机制（3GPP Forge 建 TS 38.101-5 及其 NR_bands / intra-band_CA / inter-band_CA 子目录）。
  • BCS0 两条配置落地：CA_n255(2A)（5+5 MHz）+ CA_n512（400+400 MHz）；BCS4/5 机制鼓励继续研究。
  • UE 能力影响：BandCombinationList 的 bandNR / ca-BandwidthClassDL-NR / powerClass / supportedBandwidthCombinationSet 需更新指向 38.101-5。
  • FR1-NTN（n255 5+5MHz NC CA）：给出 ΔRIBNC 表（PC3: 0/0.8/1.6 dB；PC2: N/A/[2.8]/N/A；PC1.5: 2/N/A/3.3；PC1: 按 1Tx/2Tx/4Tx 分列）；max input/ACS/IBB/NBB/OOBB 复用单载波值为起点；SAN TAE ≤3µs（type 1-H / 1-O，<10GHz）。
  • FR2-NTN（n512 400+400MHz）：CA 支持与 VSAT 类型无关；EIS 松弛 ΔRIBC = 0 dB（type 1,4）/ [0.3] dB（type 3）/ [1~2] dB（type 2,5）；OTA max input/ACS/blocking 复用单载波；SAN TAE ≤130ns（type 2-O，60/120 kHz SCS）。
  • CR/TP 分工表：TR 38.764（5.1/5.2/5.3 三段）、TS 38.101-5（Huawei 管系统参数与 5.x、LGE 管 7.x/10.x 接收、ZTE 管 7.5A/7.6A、vivo 出 running CR）、TS 38.108（ZTE 管 6.x、CATT 管 9.x）。
  • Release independence（7.6.7，Agreement）：PC1.5 自 Rel-17；HD-FDD VSAT 自 Rel-19（Ku/Ka）；NTN DL intra-band intra-SAN CA 自 Rel-18。

2.1.3 HD-FDD VSAT（7.6.4 / 7.6.5.1，Ku+Ka × FR2 numerology）（WF R4-2622015）

  • TEI20（4.6.1）：Ku 频段 FD-FDD 固定 VSAT Type 1/2/3 经 TEI20 引入（FR1+FR2），CR R4-2620851 endorsed；但"release independent 到 Rel-19"因 MCC 反对（TEI 与 release independence 冲突）转为 FFS，R4-2620852 仅 noted。
  • Ku HD-FDD：Type 7（小天线+GSO）是否支持 → FFS；Type 8（LEO-only）400 MHz 带宽不做任何 RF 要求松弛（Agreement）。
  • Ka HD-FDD Type 6：采用——最小保证 EIRP 68 dBm、EISREFSENS_50M −122 dBm、其余复用 Type 3、on-axis spurious 复用 types 4/5。
  • Ka 小天线（Type 8）：目标 SNR 是否降到 −1dB 以下（如 −6dB）FFS，EIS 仍按 −1dB SNR 推导；卫星参数（GEO/LEO-1200/LEO-600 的 EIRP 密度、G/T）给定起点；天线架构不设限（满足 20×20cm 链路预算即可）；Type 8 的 Tx/Rx 具体数值全部留待 #121。
  • TR 38.764 分工：Ku VSAT（Sharp/LG）、Ka VSAT（CSCN/CATT）、Ka 小天线（ZTE）。
  • 维护侧 3 篇 draft CR（ZTE 杂散、CATT/CSCN 辐射接收、MediaTek 成都 VSAT 类型定义）均 endorsed。

2.1.4 RRM 部分（7.6.5.2 / 7.6.6.3）（WF R4-2622018）

  • HD-FDD VSAT FR2 RRM：不再保留 legacy 的 SSB-availability 条件；以 Phase 1 结论 + 已认可的 big CR（R4-2600163）为基线；CR 分工到公司（Ericsson/LGE/Xiaomi/Nokia/Samsung/ZTE/CATT/Huawei/MTK 分列 4.2C~9.5C 各条款）；新增两条 UE feature list 条目（x-1 halfDuplexFDD-TypeA-VSAT-r20、x-2 ntn-Collision-HDFDD-VSAT-r20）；发 RAN2 的 LS 推迟至 RAN4#122。
  • NTN DL intra-SAN CA（RRM）：FR2-NTN 以"TN intra-band DL CA + 现有 FR2-NTN 要求"为联合基线；新需求用 suffix "C" 子条款；FR2-NTN CA 支持 SSB-less SCell（复用 TN FR2 legacy 基线）；FR1-NTN 的 SSB-less 与 blind SCell 留待下次。

2.2 NR_NTN_GNSS_resilient（7.18）— RF/RRM 双线收口

RF 侧（WF R4-2622020，Thales）：
- 工作计划批准：Core 至 RAN4#122（2027-01，出 38.101-5/38.133 CR），Perf 部分 #122-bis~#124（2027-08 批 CR）。
- "理想预补偿频率"定义 = 以 UE 可用信息（GNSS/参考位置、星历、显式 FAC）做理想预补偿；FAC 正确性由网络负责；UE 不承担超出网络指示的频率调整最小要求。
- 闭环：复用 ±0.1ppm/1ms 为起点（相对理想预补偿频率）；FAC 接收-生效延迟归 RRM；T_settle 内行为 FFS。
- 开环：删除 RAN4#120 的 Option 2（Msg2 前不定义需求）；Option 1（不定义）/Option 3（Msg2 后定义）保留待议。

RRM 侧（WF R4-2621828，Thales）：
- Scenario 1 为本次唯一焦点（network assistance/参考位置方案）；Scenario 2（last-known GNSS）下会开始讨论（公司分歧：HW/MTK/ZTE/CATT/E/// 推进 vs Samsung/OPPO/QC/Apple 观望）。
- Scenario 1 需求适用前提 = NGSO + 新 2 序列 PRACH 随机接入（GSO 留 FFS）。
- Te_NTN 重定义：以网络参考位置（Earth-fixed）或 common TA/Doppler（Earth-moving）为参考，去掉 UE GNSS 定位误差 margin；适用于 PRACH 与连接态。
- 渐变时间调整（Tp_NTN/Tq_NTN）→ 复用性评估；渐变频率调整不定义（Scenario 1）；TAC 复用现有 NTN 时延/精度为起点；RRM 侧不定义 FAC 精度。
- 移动性：legacy 基于位置的 cell reselection/CHO 要求不适用；Scenario 1 服务小区与 intra-satellite 邻区测量复用 legacy；inter-satellite 测量鼓励量化恶化并给出三种缓解方向（增采样/调搜索窗/松精度）；本 WID 不支持 TN↔NTN 测量与移动性；SMTC 调整由 UE 实现决定（IDLE）；连接态 SMTC 等 RAN2 结论。

2.3 LTE_TN_NR_NTN_HO（7.19，WF R4-2622104，CATT）

  • known/unknown cell 定义（Agreement）：HO 命令前 5 秒内 UE 发过有效测量报告且目标小区满足小区识别要求 → known；known 情形定义 HO 要求且不考虑 TGNSS；unknown 情形两选项（Option 1 不定义 / Option 2 有条件定义）留待下次。
  • 排除切换中途硬/软卫星切换场景；复用 legacy 原则（星历/common TA/极化/Koffset/Kmac 有效为前提）。
  • 开放项：UE 操作模式切换延迟（是否引入、[10]ms 或能力上报 0ms 选项）；E-UTRAN→NR NTN 的 SSB/小区数基线（[4] cell / [7] SSB / GEO 4 SSB / NGSO 1 星）；side condition 复用性。

2.4 IoT_NTN_Ph4（7.20，WF R4-2622021，vivo）

  • PC0.5 MPR 敲定（Agreement，单音/多音全表）；A-MPR：NS_02N 无需 A-MPR；NS_10N/NS_15N 起点值给出；"RAN4 侧在任一频段 A-MPR 完成即可结项"。
  • PC0.1 MPR：倾向同意但允许公司核对至 #121（tentative）。
  • 热/功率处理（GEO 语音）：目标=尽可能多的 SA 编解码速率与 bundling 周期；方案二选一（Option 1 定义最小 UL 占空比如 20% + 评估周期 80/160ms；Option 2 只在 RMC 处理 + core 要求加注）；RMC 与 Issue 3-1 结论联动、下次继续。
  • 相关 CR：CATT 的 B256/B255 PC0.5/PC0.1 CR（R4-2621109）postponed；Ericsson（38.863 共存结果）、vivo（38.863 CR）endorsed。

2.5 NR_NTN_IoT_NTN_ext_guard（7.12，WF R4-2622035 + WP R4-2622105，Sony）

  • 工作计划批准（Option 1）：#120-bis 定义/原则 → #121 取值 → #122 定值并出 38.101-5/36.102 CR + 38.863 TP。
  • 定义（基线）：扩展保护带 = 相对 UE 信道带宽边缘的频偏。
  • IoT NTN：至少 SIB 广播（NS 还是新 IE 待定）；UE 能力三选项 FFS；UE 行为三选项（Nordic/Sony/Qualcomm 方案）FFS；release independence 推迟到信令设计明确后；cat-M1 评估推迟到未来版本；评估起点 100 kHz（目标：b255/b249/254 全功率等级 0 dB A-MPR）。
  • NR NTN：聚焦 5 MHz 带宽，起点 1000 kHz（讨论中出现 500/1000 kHz 两值选项）；A-MPR 目标四选项（含"A-MPR ≤ MPR"）；每频段 1 个还是 2 个保护带值待定。

2.6 NTN_bands_Features_R20（5.5，WF R4-2622079，Apple）

  • 已落地（Agreement/endorsed）：n255 的 3 MHz+PC2/PC1 组合——无需新 A-MPR 工作（NS_10N/NS_15N 与 n251 共用）、RSD 复用 n251 3MHz 值；NS_11N PC2（b249/254）A-MPR 采用（3.75kHz ≤20.5 / 15kHz 单音 ≤16.5 … 12 音 ≤6）；b252 的 NS_06N/07N/08N 对 PC2 无需 A-MPR；b253（NS_09N）PC1.5 复用 n255 的 A-MPR。draft CR endorsed：Apple（RSD 澄清 ×2、n254 PC2，R4-2620738/739/740）、ViaSat（b253 PC1.5，R4-2621399/1400；n255 3MHz PC2/PC1，R4-2621402）。

2.8 6G NTN（议程 8，FS_6G_Radio）

  • NTN 共存 RAN task [364]（WF R4-2622084 批准，AT&T+Ericsson 主持）——场景 = NTN DL → TN DL（2.1GHz：n256 → n66）与 NTN-NTN DL-DL：
  • SAN 天线：以 TR 38.922 相控阵模型为基线，多波束机制 FFS；初始评估用相关值 0.0/1.0 两档。
  • SAN 发射参数：初始评估用 R1-2606916 的 Set 6G-1；允许公司选择波束数（恒定 PDF 受限 / 恒定 EIRP 密度两法），须以 PFD 目标（−89 或 −85.5 dBW/m²/MHz，ViaSat 提出后者）验证地面信号水平，并对齐 TR 38.863 的 7 波束 C/I 目标。
  • 受害 TN：19 站 57 扇区布局（关 wrap-around）；边缘噪声受限两种刻画（用户半径 2.1~2.7×ISD 或 RSRP 5% −120dBm+3dB noise rise）；ISD 5/7.5km、站高 30/45m；BS 天线 AAS（Rel-19 IMT 研究 TR 38.922 cl.4.4.1）/non-AAS（TR 38.863 cl.6.2.3.2）双模型；UE 各向同性 0dBi。
  • NTN-NTN：加载因子 100%（最坏情形）；性能指标 = 平均与 5%-ile 吞吐损失 <5%；SAT ACLR 推导值 24.2 dB（GEO 受害 30°、LEO-600 攻击 90° 最坏组合），考虑单星收紧；SAN 天线基线取 Option 2（TR 38.863 Bessel 圆孔径模型）。
  • 未决（下次继续）：干扰求和法、缩放因子、覆盖几何（Huawei vs Ericsson 两案待调和）、UE 去极化损失建模等。
  • MEO 共存（8.4.3.2）：12 篇全部 noted、未产出任何结论；Thales（R4-2621511）直言部分假设"不相关、在 RAN4 现有工作量下讨论完全低效"——该子课题实质上被降优先级/挂起，值得持续跟踪。
  • 6G NTN UE RF（8.3.6，102-A 总结 R4-2621590）：总基调 = TN/NTN 需求尽量和谐化（OPPO/ZTE），个案例外需 NTN 特性或监管理由；议题含设备类型简化（VSAT 分类重构）、功率等级对齐、UL-MIMO/CA（等 SNO 商业需求反馈）、杂散（vivo 主张直接套用 TN 结论、ZTE 建议自适应 LO 方案）、其他依赖（占空比热缓解、GNSS-free 与 5GA GNSS 弹性研究对齐——Samsung 提醒避免重复）。
  • 6G NTN 频谱（8.5.4，104-A 总结 R4-2621592）：焦点是 6G NTN 频率范围如何定义——OPPO（10GHz 单一断点、Ku 只按 FR2 引入）；ZTE（下界维持 5G NTN、上界随 SNO、频段组合框架等 Rel-20 WID 共识）；Nokia（沿用现 NTN FR、对齐讨论推迟到 WI 阶段）；CATT（复用 FR1-NTN/FR2-NTN、尽量单 FR 频段、考虑全部现 NTN 频段 refarming、Ka/Ku 优先）；LGE（研究把 10GHz 以上 VSAT 合并进 FR2-NTN、引入 "s" 前缀频段命名）。

3. 公司态势与争议焦点

文稿量 Top（NTN 专属议程，联合署名按公司计）：CATT 30 / Huawei 24 / vivo 20 / ZTE 19 / Ericsson 18 / MediaTek 17 / Thales 16 / Apple 15 / Qualcomm 15 / LGE 13 / Samsung 11 / CHTTL 10 / Sharp 8 / Viasat 8 / OPPO 7 / Nokia 7 / Sony 6 / SpaceX 5；卫星运营商侧（Viasat/SES/AST/Iridium/SpaceX/Eutelsat/JSAT/Globalstar）全面活跃于 VSAT 类型、功率等级与 A-MPR 议题。

主要争议点（本会实录）：
1. PC1.5 dual Tx 的 ULFPTx 模式范围：Samsung/Ericsson/CATT 主张"只做 mode 1"，Huawei/Qualcomm 主张保留 mode 2（"不能因为信令可用就定需求"vs"全功率发射是 UE 能力、不必在规范排除"）→ 结论折中为 PC1.5=mode1、PC2 含 mode1,[2],0。
2. 相干 MIMO 要求照搬 TN：Viasat 明确反对未研究即复制 TN 相干要求到 NTN → WF 保留"各公司分析适用性、下会出结果"。
3. Ku Type 7（小天线+GSO）：Qualcomm/Thales 支持引入，Huawei/ZTE 反对（"Ku FR1 已有"、"链路预算不闭合"）→ FFS。
4. Ka 链路预算的目标 SNR：Thales/Sharp 主张评估用低 SNR、定值仍按 −1dB；Huawei 要求更强论证 → "低于 −1dB 可行性 FFS，EIS 按 −1dB"。
5. GNSS Scenario 2（last-known 位置）：Qualcomm/Apple/Samsung 主张等 RAN1 明确"sufficient and valid"再谈；Huawei/MTK/ZTE/CATT/Ericsson/Xiaomi/vivo 主张下会即开始 → 折中"本次聚焦 Scenario 1，下会开始 Scenario 2"。
6. TEI 与 release independence 的规则冲突：MCC 当场指出 TEI20 特性不能 release-independent（引 RP-260762 先例），CHTTL 以"移动 VSAT 已 RI 到 Rel-19"反驳 → Fixed_VSAT_Ku 的 RI 留 FFS，是本次 TEI20 新引入中的一个制度性风险点。
7. MEO 共存研究效率：Thales 公开质疑讨论低效，与 RAN4 工作量的矛盾显性化 → 该议题被挂起。
8. 6G NTN 与 TN 的频段/需求和谐化：总体共识"能合则合"，但 Ku 频段 FR1-NTN/FR2-NTN 双轨并存的整理方向（LGE 主张合并）尚无结论。
